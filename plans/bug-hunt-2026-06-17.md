# Wide-sweep bug hunt - 2026-06-17 (resolved + follow-ups)

The original consolidated audit (~140 findings across 12 read-only review
slices over the post-refactor churn) has been worked down to landed commits
in 13 fix slices. The resolved findings now live in git history - each
commit message names the shortlist numbers and files it closed. This doc
retains only the remaining open follow-ups and the items deliberately kept
as-is, so it reflects current gaps, not history.

All ten shortlist items plus the second-pass additions are fixed and landed:
idempotency table (#4), MIME encoded-words (#7), net redirect same-origin
(#6), SASL iteration cap, SMTP XOAUTH2 (#10), IMAP draft byte-exactness (#1)
and partial-send (#2), Graph EWS 200-OK classification (#2-EWS) and foreign
membership reconciliation (#5 partial) and scheduled send-as routing,
JMAP stateMismatch (#8) and reschedule (#3), CalDAV phantom Destroyed (#9).

## Rules for agents touching this area

These earned their keep during the fix slices - keep applying them:

1. Contract docs (`reference/*.md`, above all `error-model.md` / `sync.md`)
   and existing tests are authoritative; a finding that contradicts them
   loses. Don't rewrite a contract or a passing test to match a finding.
2. Confirm against the contract, not the finding's own rationale.
3. Fix only what is named and confirmed; don't generalize one case into a
   sweeping rule.
4. An existing test you must modify is a red flag - justify it explicitly.
5. A shared-crate change (`types`/`net`/`sasl`/`sync`) is pinned by
   downstream tests; run the full-workspace `brokkr check`, never `-p`.

## Open follow-ups (need a decision or a larger change)

- **F1b - Graph shared-mailbox MUTATION routing.** F1 landed option (b):
  hydration / blobs / webhook resources now foreign-encode the owning
  mailbox into the message id and route to `/users/{owner}`. But the
  mutation path (`mutate.rs` bulk_set_flags / bulk_move / bulk_destroy,
  `pim.rs` per-message writes) and the typed `message_hydrate` /
  `thread_hydrate` methods still build `/me/messages/{id}`. Post-F1 those
  receive the foreign-encoded id, so a shared-mailbox flag/move/destroy now
  builds a malformed `/me/messages/{owner\u{1f}native}` URL (previously a
  clean `/me` 404). They need the same `parse_message_id` + `client_for_owner`
  decode-and-route as the read paths. graph.md already names shared-mailbox
  draft mutations a follow-up; this widens it to flag/move/destroy and the
  typed hydration methods. Should be done next - it's the natural completion
  of #5 and removes the malformed-URL hazard.

- **F5 - Shared DAV propstat/status parser.** carddav's `is_success_status`
  and `parse_collection_ctag` are now robust in place, but the
  propstat-success gating is duplicated across both DAV crates. A shared
  parser module would remove the drift risk.

- **F2 (likely WONTFIX) - `ScopeChange` single membership.** Widening
  `ScopeChange.membership` to `Vec<MembershipScope>` would touch
  types+jmap+graph+engine, but slice 6 showed the single `Folder(id)` is
  the correct routing membership (the engine covering rule would not cover
  a `Mailbox(owner)` tag against a folder cursor). Only worth it if change
  events must carry the owner tag for some future consumer.

- **Minor - long non-ASCII display name folding.** The MIME encoded-word
  fix fully handles Subject; a pathological non-ASCII display *name*
  (~500+ chars) in an address header can still have its folds flattened by
  the address-header path. Names are near-universally short, so low impact.

## Deliberately kept as-is (documented-intentional; reopen only to revisit)

- IMAP `scope_lifecycle_stream` stub - IMAP discovers folders at
  open/reopen; mid-session mutations surface via push IDLE (documented in
  code + sync.md).
- IMAP `send_message` does not pre-validate scheduled time - the relay's
  EHLO is authoritative per imap.md.
- IMAP `FetchLimit` -> ClientBug - no cleaner kind; valid request, oversize
  response.
- IMAP `restamp`/`into_builder` drops the SMTP idempotency override - safe
  while Send/DraftSend are both non-idempotent; documented at the call
  site. A real fix is a `bifrost-types` change error-model.md deliberately
  scopes out.
- Graph `cursor.rs` `scope_for_kind(Events)` lossiness - compensated by
  `event_aliases`; the Events cursor structurally can't record object type.
- JMAP three distinct scope-less not-found shapes - different wire sources,
  all terminal, documented divergence.
- Google `notAuthorizedToAccessThisResource` classified PermissionDenied -
  mitigated by the first-page directory-absence gate; reclassification is
  an error.rs scope decision.
- DAV cross-origin Authorization strip - reqwest's default already strips
  it; not an open leak.
