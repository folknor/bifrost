# Wide-sweep bug hunt - 2026-06-17

Consolidated findings from a read-only audit of the post-refactor churn
(~16k net new lines over the last 17 commits: SASL channel binding /
SCRAM-PLUS, SMTP+IMAP auth, Graph EWS / public folders / Autodiscover /
cloud, JMAP+Graph+IMAP foreign mailboxes, shared `mime`/`compose`
helpers, Google Drive hosting + People contacts, DAV first-class sync).

Coverage was split into 12 non-overlapping slices, one review agent each.
This document collects every reported finding, de-duplicated across
slices.

**Status: UNVERIFIED.** These are the reviewers' findings with their own
confidence ratings. Nothing here has been independently confirmed against
a second read or a compile, and nothing has been fixed. Treat line
numbers as "as of this commit" and re-confirm before acting. Confidence
(H/M/L) is the reporting agent's estimate that the item is real, not a
false positive.

Labels: **bug** (defect) / **gap** (missing handling or doc divergence) /
**smell** (fragile/inconsistent, not yet wrong) / **nit** (cosmetic).

## Highest-priority shortlist

These are the items most worth confirming first - correctness or
security impact, high confidence.

1. **IMAP `draft_send` corrupts non-UTF-8 drafts on the wire** - `crates/imap/src/account/pim.rs:422` reconstructs the *transmitted* body via `String::from_utf8_lossy`, so any 8-bit/binary draft octet becomes U+FFFD in the sent message while the Sent-folder APPEND keeps verbatim bytes (silent divergence). (H)
2. **Graph EWS `ErrorAccessDenied` quarantine never fires for the common error shape** - `check_soap_fault`/`parse.rs` only inspect SOAP `<faultcode>`/`<faultstring>`; an `ErrorAccessDenied` delivered as `ResponseClass="Error"` / `<m:ResponseCode>` inside a 200 OK is never classified, degrades to `MalformedXml → Protocol(ParseFailed)`, and the documented `ScopeRevoked → DisableScope` quarantine is bypassed. (H)
3. **JMAP `reschedule_send` can double-send** - `crates/jmap/src/sync/pim.rs:1864-1889` batches the old-submission cancel with the new create but only checks the create; a failed cancel + successful create leaves two live submissions for the same email. (H)
4. **Central idempotency table omits destructive ops** - `crates/types/src/error/scope.rs:189-222` `is_idempotent` lacks `BulkDestroy`, `Expunge`, `DraftDiscard` (while `BulkMove` is present), so an in-flight transport/server drop on a destroy routes to `Retry(SameRequest)` instead of `Reconcile(CheckTarget)`. Affects every crate via the central recovery `derive`. (H)
5. **Graph foreign/shared-mailbox routing hardcodes `/me`** - hydration (`get.rs:78-104`), blobs (`blob.rs:258,282`), and webhook subscription resources (`push.rs:284-301`) all use the primary `/me` prefix, so shared-mailbox messages 404 or mis-resolve; the webhook path even percent-encodes the `\u{1f}`-bearing foreign id into the URL. (H)
6. **net redirect cross-host check is case-sensitive** - `crates/net/src/redirect.rs:211` compares `host_str()` byte-for-byte while the allowlist is case-insensitive; a mixed-case same-host redirect is treated cross-host (can reject valid hops; strip direction is fail-safe). (H logic)
7. **MIME RFC 2047 encoded-words are unbounded and not boundary-split** - `crates/types/src/mime.rs:309-316` emits one `=?UTF-8?B?…?=` blob with no 75-octet cap and no UTF-8-safe splitting; long non-ASCII Subject/display-name breaks strict parsers and the 998-octet line limit. Shared assembler, so it hits IMAP and Google send. (H)
8. **JMAP surviving `stateMismatch` kills the whole mutation stream** - `crates/jmap/src/sync/mutation.rs:154-164` propagates a second method-level `stateMismatch` as `Err`, terminating the bulk stream, instead of the documented per-item `Failed(ConcurrencyConflict)`. (H divergence)
9. **CalDAV sync-collection emits a spurious `Destroyed`** - `crates/caldav/src/account.rs:1076-1081` pushes `Destroyed` on a 404/410 entry even when the href was never in the snapshot. (H)
10. **SMTP XOAUTH2 failed-auth `334` is unhandled and misclassified** - `crates/smtp/src/transport/smtp/client/connection.rs:1486-1492` (+ async `:1583-1589`) errors through a bare `?` (no `abort()`, no `Auth` phase tag), so a credential rejection maps to `Request(Malformed) → ClientBug`; the `AQ==` cancel is never sent (only OAUTHBEARER handles it). (H)

## Cross-cutting patterns

Recurring shapes worth a single design decision rather than N point fixes:

- **Foreign/shared-mailbox routing is half-wired.** The discovery/cursor
  paths namespace the owning mailbox into the `FolderId`, but several
  downstream paths ignore it: Graph get/blob/push route to `/me`
  (#5 above); Graph inventory/changes membership uses the *native* folder
  id while discovery uses the *foreign-encoded* id, so they can't
  reconcile (`graph/.../inventory.rs:185-196`, `changes.rs:75,91`); JMAP
  emits unqualified native mailbox memberships alongside the owner tag, so
  a cross-account id collision still conflates
  (`jmap/.../inventory.rs:157-171`); JMAP foreign mutations and Graph/JMAP
  foreign-mailbox lifecycle are unwired (documented follow-ups). A
  previously-seeded-then-unregistered JMAP foreign scope silently
  misroutes to the primary account (`jmap/.../account.rs:126-149`).

- **Scheduled-send cancel/reschedule loses the routing handle.** JMAP
  runs scheduled send/cancel/reschedule against `self.mail` while the
  resolved `self.submission` handle sits unused
  (`jmap/.../account.rs:627-653`, `pim.rs`); Graph routes
  cancel/reschedule of a *send-as* scheduled message through the primary
  `/me` client even though the draft lives in the shared mailbox
  (`graph/.../pim.rs:402-437`). Same class of bug in two crates.

- **`parse_draft_for_submission` (IMAP) is fragile.** `from_utf8_lossy`
  corruption (#1) plus a body-split that mishandles mixed line endings /
  header-only drafts (`imap/.../pim.rs:423-427`) plus CRLF/LF mixing in
  the rebuilt body (`strip_bcc_header`, `imap/.../pim.rs:471-491`). One
  function, three reports.

- **Auth-failure error classification leaks through bare `?`.** SMTP
  `auth_legacy` (#10) and several IMAP submission paths raise auth/parse
  errors without the phase tag the account-error mapping needs, so
  credential rejections land on `ClientBug`/`ParseFailed` instead of an
  auth/policy lane.

- **Clock-source for jitter/timing.** sync engine reopen jitter uses
  `SystemTime::now().subsec_nanos()` (`sync/.../engine.rs:2113-2126`),
  vulnerable to clock jumps, whereas `bifrost-net` deliberately uses an
  `Instant`-based delta. Inconsistent thundering-herd guard.

- **Capability gating is asymmetric.** Some IMAP PIM mutators gate on
  `pim_methods.*`, others (`set_keyword`/`set_importance`/`set_is_read`,
  `search_messages`) don't; harmless today (flags hardcoded true) but a
  latent trap.

- **DAV crates run their own HTTP stack.** CalDAV/CardDAV build their own
  `reqwest::Client` and bypass `bifrost-net`'s hardened redirect loop
  (trusted-host allowlist unenforced; hop counts disagree 10 vs 5).

## crates/sasl

Crate is in good shape; core SCRAM/PLUS/CRAM/OAuth crypto verified correct
(RFC 5802/5929/2195 vectors pinned, `c=` framing single-sourced, EdDSA /
unknown-OID hard errors, zeroizing `Secret`).

- **gap (M)** `scram.rs:189` - `verify_server_final` compares the server
  signature with non-constant-time `Vec` `!=`. `actual` is
  attacker-controllable (`v=` field); a timing oracle could help a MITM
  forge the server signature to impersonate the server. The proof compare
  (`secret.rs:66`) is constant-time, so the asymmetry is notable. Low
  practical exploitability.
- **smell (H/low-impact)** `channel_binding.rs:82-89,100-110` - the
  OID→hash table includes bare *digest* OIDs (e.g. `2.16.840.1.101.3.4.2.1`).
  A conforming X.509 `signatureAlgorithm` never carries a bare digest OID;
  accepting them is harmless but widens the set and makes the
  `signature_oid_maps_to_hash_family` test pin entries that can't occur.
- **nit (H)** `channel_binding.rs:233-380` - DER tests only use short-form
  lengths; the long-form length path in `read_tlv` (`:193-221`) - multi-byte
  accumulation, `num_len_bytes > 4` rejection, indefinite-form rejection,
  `usize::try_from` narrowing - is untested (the trickiest off-by-one /
  overflow surface).
- **nit (H)** `scram.rs:197-201` - `scram_field` rebuilds `format!("{key}=")`
  per lookup, 4-5×/message. Allocation churn only.
- **nit (intentional)** `secret.rs:66-79` - constant-time `PartialEq` leaks
  `max(len(a),len(b))`; standard accepted limitation (lengths aren't secret).

## crates/types (shared: mime / compose / recovery)

`recovery::derive` table, four-helper mutual-exclusivity/exhaustiveness,
`message_key` derivation, Bcc handling, Message-ID domain sourcing, and
`account_compose` routing/fan-in all verified correct against the doc.

- **bug (H)** `mime.rs:309-316` - RFC 2047 encoded-words have no 75-octet
  cap; one `=?UTF-8?B?…?=` blob on a single unfolded line. Long non-ASCII
  Subject/name → strict-parser/relay rejection + 998-octet line overflow.
  (See shortlist #7.)
- **bug/gap (H)** `mime.rs:309-316` - encoded-word never split on UTF-8
  char boundaries; the "encode whole value as one word" approach makes both
  the length and the no-split-multibyte invariants unsatisfiable.
- **bug/divergence (M-H)** `mime.rs:301-307` - `encode_phrase` always
  quotes ASCII display names (even atom-shaped), and uses `=?UTF-8?B?` for
  non-ASCII, diverging from `reference/smtp.md:113` ("phrase text when
  atom-shaped … avoids DKIM-breaking quoted-string rewrites") and from the
  bifrost-smtp builder. Two send paths produce divergent From/To phrases.
  Test at `:422` pins the (divergent) quoted form.
- **bug (latent, H)** `error/scope.rs:189-222` - `is_idempotent` omits
  `BulkDestroy`, `Expunge`, `DraftDiscard` (and the flag/label/importance
  setters); `BulkMove` is present. Destroy/expunge/discard treated
  idempotent → blind `Retry(SameRequest)` on an in-flight drop instead of
  `Reconcile`. (See shortlist #4.)
- **smell (M)** `error/recovery.rs:748-755` - `transient_retry_or_reconcile`
  routes an `Acknowledged` attempt to `Retry(SameRequest)` regardless of
  idempotency; reachable from `derive_server` for
  Unavailable/RateLimited/QuotaExhausted, so a `Server(QuotaExhausted)` +
  `Attempt(Acknowledged)` could blind-retry a non-idempotent acknowledged
  send.
- **nit (M)** `mime.rs:251-254` - attachment `filename`/`mime` embedded in
  `name="…"`/`filename="…"` without escaping embedded `"` (CRLF is stripped,
  so injection-safe, but quote-breaking malforms the params).
- **smell/gap (M)** `mime.rs:344-357` - `RenderedMessage.message_id`
  returned to the caller is the *unsanitized* `generate_message_id` output
  (the header itself is sanitized). Carries weird chars from `from.address`.
- **bug/nit (L)** `mime.rs:91-93,126-130` - a Bcc-only send renders no
  `To:`/`Cc:` and no `undisclosed-recipients:;` placeholder (legal RFC 5322
  but some MTAs balk).
- **smell (L)** `mime.rs:332-339` - boundary token is predictable and not
  checked against body content; safe today only because all parts are
  base64. Fragile if a non-base64 part is ever added.
- **smell (L)** `account_compose.rs:90-100` - merged discovery stream drops
  any sub-account checkpoints (intentional for discovery, but undocumented
  loss).
- **smell (L)** `account_compose.rs:114-138` - subs drained sequentially
  then buffered; a sub that never yields `Done`/`Terminated` blocks the
  whole merged stream (no timeout); first byte delayed until slowest sub.
- **nit (L)** `compose.rs` - shared assembler doesn't centrally
  reject/assert a `scheduled`/`send_as`-bearing request; relies on each
  consumer validating first (documented division, but a footgun).
- **nit (L)** `mime.rs:186-191` - `in_reply_to`/`references` not validated
  as well-formed message-ids (injection-safe via `sanitize_header`).
- **nit (L)** `cloud.rs:31-35`, `directory.rs:23` - `CloudUploadMeta.size`
  and `DirectoryCard.email` "always present/equal" invariants are unenforced
  honor-system.
- **observation (L)** `cause.rs` - `ImapResponseCode::code()` emits codes
  with embedded spaces (e.g. `"METADATA LONGENTRIES"`); diagnostic-only, but
  whitespace-splitting consumers would mis-parse.

## crates/imap - auth + submission

SCRAM-PLUS ordering/downgrade protection, PLUS binding resolution, GS2
sourcing, CRAM-MD5, ACL parse, MYRIGHTS gating, credential/token-source
reuse, Bcc handling, scheduled-send absolute time, APPENDUID fallback, and

- **bug (H)** `account/pim.rs:422` - `parse_draft_for_submission` rebuilds
  the transmitted body via `from_utf8_lossy`; non-UTF-8 octets → U+FFFD on
  the wire while the Sent APPEND keeps verbatim bytes. Hits every
  `draft_send`, not just Bcc drafts. (Shortlist #1.)
- **gap (H)** `types/auth.rs:128-145` + `connection/auth.rs:40-69` -
  OAUTHBEARER (RFC 7628) is not on the selection path; `AuthMechanism` has
  only `XOAuth2`. A server advertising only `AUTH=OAUTHBEARER` fails with
  `MissingCapability`. `reference/imap.md:61` lists OAUTHBEARER (doc/code
  divergence; `bifrost-sasl` even ships `oauthbearer_payload`).
- **smell (H)** `connection/auth.rs:144,228,364` - public `login` /
  `authenticate_plain` / `authenticate_cram_md5` enforce no TLS gate /
  policy; only `authenticate_best` gates. A direct caller sends reusable
  credentials over plaintext / runs CRAM-MD5 unencrypted. Likely intentional
  (direct == opt-out) but an unguarded leak surface.
- **smell (M)** `connection/auth.rs:72-128` - ladder built from
  `server_profile()` but `require_auth_mechanism` checks the live snapshot;
  on skew an `Attempt` rung's `MissingCapability` `?`-aborts the whole
  ladder instead of falling through to PLAIN-over-TLS.
- **smell (L-M)** `account/pim.rs:471-491` - `strip_bcc_header` re-emits the
  header/body separator as CRLF but keeps verbatim header lines; a bare-LF
  draft goes out with mixed endings (deciding factor: whether bifrost-smtp
  normalizes the DATA body).
- **smell (H behavior / design)** `account/submission.rs:198-202` -
  `SubmissionTls::Plaintext` unconditionally sets
  `dangerous_allow_insecure_auth(true)`; reused IMAP password sent cleartext
  with no gate analogous to `allow_cleartext_without_tls` (choosing
  Plaintext is the opt-in).
- **nit/gap (H not-validated / L defect)** `account/pim.rs:210-256` -
  `send_message` doesn't call `validate_scheduled`; a past instant becomes a
  past `HOLDUNTIL` left for the relay to reject (doc says relay is
  authoritative).
- **assumption to confirm** `MyRightsConsumer` correlates `self.mailbox`
  against the response `MailboxName` via `inbox_eq`; correct only if the
  parser decodes the response mailbox to the same UTF-8 form (parser is
  outside the slice).

- **nit (L)** `account/factory.rs:155-159` - `discover_shared_folders`

# Second pass - error-model & sync-conformance re-audit

A second hunt re-ran 10 of the 12 slices (all except shared-types and
DAV+net+sync, which had already read `error-model.md`/`sync.md`), this time
with `reference/error-model.md` and `reference/sync.md` as required reading
and an explicit error-classification / sync-contract conformance lens. Each
re-audit confirmed several first-pass items against the authoritative
contract and surfaced new ones. Only the **new** findings and notable
**confirmations** are recorded below; items already covered above are not
repeated.

## Second-pass highest-priority additions

1. **IMAP `scope_lifecycle_stream` is an empty stub** - `crates/imap/src/account/scopes.rs:83-93` spawns a task that only waits on `shutdown` and drops `tx`; it never emits `ScopeLifecycle::{Created,Renamed,Deleted}`. Per `sync.md`, those drive `lifecycle_reopen → RestartScope` for newly-appeared folders and tear down deleted-folder polls. A folder that appears after `attach` (a newly-shared/other-user mailbox) is invisible to the engine until a full account reopen. (M - possibly intentional "IMAP discovers only at open/reopen", but undocumented and reads as a stub.)
2. **IMAP multi-recipient partial send is flattened to a blanket `Err`** - `crates/imap/src/account/submission.rs:242-258` collapses the three-lane `BatchOutcome` from `send_raw_batch_with_options` to the first failed/uncertain recipient's error, discarding the `succeeded` lane. With a single shared DATA, recipient A can be accepted+delivered while B's RCPT is rejected; returning `Err(B)` lets the engine re-drive the whole send and re-deliver to A when B's error is retryable/uncertain - the non-idempotent double-send the transmission-state machinery exists to prevent. (H - confirmed wire shape; severity depends on B's error class.)
3. **SASL unbounded SCRAM `i=` iteration count** - `crates/sasl/src/scram.rs:134-144` parses any `u32` and feeds it straight to PBKDF2 with only `==0` rejected; a hostile/misconfigured TLS peer can send `i=4000000000` and pin a core for minutes per attempt. RFC 7677 wants a sane ceiling. (M.)
4. **EWS application errors in 200 OK never classified** - already shortlist #2; the re-audit confirmed end-to-end that the correctly-built `ErrorAccessDenied → ews_shared_scope_error → ScopeRevoked → DisableScope` path is *unreachable from the wire* (the passing test constructs the `EwsError::SoapFault` directly, bypassing `execute`), and that a revoked/throttled public folder is misread as empty → spurious mass-`Destroyed`. (H.)
